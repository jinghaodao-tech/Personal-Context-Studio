# ADR-014: 正規化した正本と派生非正規化モデルを分離する

## ステータス

承認済み。

## 背景

PCSはMarkdownを人が読める正本として保持し、SQLiteを派生索引として利用します。さらに、関係データ、インポート、スナップショット、読み取り処理では、事前計算や結合済みのデータが有効です。すべてを完全に正規化するとローカル読み取りやエクスポートのコストが増えます。一方、非正規化データを正本として扱うと、複数の正本が生まれ、整合性と出所が不明確になります。

## 決定

正本となる記録と関係データは、権威ある境界では正規化して保持します。非正規化は、再構築可能な読み取りモデル、検索索引、スナップショット、インポート・エクスポート用ペイロードに限って許可します。

非正規化された表現には、必ず出所、再構築または更新の経路、鮮度の境界を持たせます。書き込みは先に正本へ反映し、派生データが暗黙に正本へ昇格してはいけません。

## 代替案

- すべての読み取り経路を完全に正規化する: 繰り返しのJOINや再構成が増え、ローカル読み取りとエクスポートが不必要に重くなるため採用しない。
- 非正規化レコードを正本にする: 重複フィールドが乖離し、出所が曖昧になるため採用しない。
- メタデータなしの重複を都度許可する: 古いデータが確認済みのコンテキストと誤認されるため採用しない。

## 結果

- 正本データの所有境界が一つになり、独立して検証できます。
- 検索やスナップショットは、正本を変更せず効率的な非正規化データを利用できます。
- 派生表現ごとに、再構築、鮮度、失敗時の挙動をテストする必要があります。
- 派生索引が古くても、可用性や検索の鮮度に影響するだけに留め、正本のMarkdownや確認済み記録を書き換えてはいけません。

## 見直し条件

正規化された正本境界が支配的なコストだとプロファイリングで判明した場合、または出所、再構築可能性、整合性を同等に保証できる将来のストレージアダプターができた場合に見直します。
