# ADR-018: 転置インデックスが存在しないことの記録

## 背景

検索実装は記事ごとに正規化済みまたは事前計算済みのトークンを保持していますが、トークンから該当文書一覧を引く転置インデックスは保持していません。トークンキャッシュやコーパス統計は転置インデックスとは別物です。

## 決定

現在のアーキテクチャを明記します。BM25のスコアリングは検索パイプラインの実行ごとに、利用可能な記事のトークンデータを走査しています。転置インデックスの検索やposting listの更新は、現在の検索契約には含まれていません。

導入しない理由は、現在のコーパスが約216件で記事走査が支配的なコストだと実測されていないこと、BM25のスコア計算自体には転置インデックスが必須ではないこと、導入するとposting listの更新・記事変更時の整合性・メモリ使用量・構築コストが増えることです。実測プロファイリングで明確な効果が確認できるまで保留します。

これは転置インデックスが不要だという主張ではありません。導入する場合は、実測したワークロードと、厳密な検索結果を維持する回帰テストに基づく別の判断とします。

## 結果

- 検索処理量は記事数と記事のトークンデータに依存します。
- posting listの更新経路がないため、記事変更時の索引鮮度と整合性は単純です。
- LSH重複排除は転置インデックスの代わりではなく、ランキング前の重複比較候補を絞る処理です。
- 将来転置インデックスを導入する場合は、ランキング結果、記事変更時の更新、メモリ使用量、構築コストを別々に検証します。

## 撤回条件

対象コーパス規模で記事走査が検索コストの支配要因になったことを、本番相当のプロファイリングで確認した場合に再検討します。
