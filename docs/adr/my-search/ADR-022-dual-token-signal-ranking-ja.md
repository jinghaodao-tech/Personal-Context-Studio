# ADR-022: 2種類のトークンを保存し、正規化BM25を合成する

## 背景

日本語検索では、形態素解析トークンが意味的な精度に役立ち、文字N-gramが未知の複合語や表記揺れを補います。検索モードを切り替えるたびに再計算すると無駄な処理が増えます。また、展開済みの `tokens_json` だけでは、どの信号が順位に寄与したか分かりません。

## 決定

書き込みまたはバックフィル時に、形態素解析トークンとN-gramトークンの両方を保存し、それぞれの文書長も保持します。既存の `tokens_json` と `doc_length` は、後方互換性のためN-gram側の表現として残します。

検索時は2種類のトークンについてBM25を独立に計算します。各信号をその検索コーパス内の最大値で0〜1に正規化してから、モード別の重みで合成します。実装モードは形態素解析の精度を重視し、理論・トレンドモードは未知語に対応するためN-gramの重みを高くします。ランキング詳細には、生スコア、正規化スコア、重み、合成スコアを出力します。

## 代替案

- モード変更時に再トークナイズする: 検索時に書き込み相当の処理を繰り返すため採用しない。
- 展開済みN-gramだけを保存する: 形態素解析の挙動を分離して評価・重み付けできないため採用しない。
- 生BM25をそのまま加算する: 2つのトークン空間は長さとスコア範囲が異なるため採用しない。

## 結果

- 保存済みコーパスを変えずにトークン方式を比較できます。
- JSON保存量と書き込み・バックフィル時間は増えるため、マイグレーションとコスト計測が必要です。
- コーパス内正規化のため、スコアは同一検索内では比較できますが、無関係なコーパス間では直接比較できません。
- 本番重みを変更する前に、版付き50ケースのreal評価でトークン方式を比較します。

## 見直し条件

保存量または書き込みコストが、再現可能な品質改善を上回ると実測された場合、または単一トークナイザーで版付き評価を十分満たせることが示された場合に見直します。
