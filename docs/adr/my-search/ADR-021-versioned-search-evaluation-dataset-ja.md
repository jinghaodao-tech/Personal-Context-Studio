# ADR-021: バージョン付き層別検索評価データセットを使う

## 背景

以前の検索品質評価は、少数の手書きケースに結果が強く依存していました。1件の正誤で集計値が大きく変わり、ケースが易しいのか、曖昧なのか、専門語を含むのか、正解が複数あるのかも明示されていませんでした。これはトークナイザーやランキングを比較するときに危険です。

## 決定

57文書の合成データセットは、ランキング診断とend-to-endゲートとして維持します。別に、50件以上の手書きクエリによる実コーパスのリリースシグナルを管理します。realデータセットの版は `anonymized-card-corpus-v2-50-manual-queries` とし、元の20ケースを比較可能な状態で残すため、`real-queries.json` と `real-queries-v2.json` に分けて保存します。

新しいrealケースには、種類、難易度、言語、正解文書が単数か複数かを記録します。クエリは一意にし、正解文書IDを明示します。文書トークンからの自動プローブは、関連性ラベルではなく診断用途に限定します。

## 代替案

- 11件または20件のままにする: 1件の影響が大きすぎるため採用しない。
- 文書トークンからすべてのクエリを生成する: 循環的で、実際より易しいラベルになるため採用しない。
- 合成データセットを置き換える: ランキングとパーサの回帰を分離して診断できるため採用しない。

## 結果

- トークナイザーやランキングの変更を、以前より振れにくい実コーパス評価で確認できます。
- 難易度と正解数ごとの結果を、集計値に隠さず報告できます。
- 手書きラベルの維持は必要であり、コーパスや検索行動の変化に応じて更新します。
- このスコアは普遍的な本番精度ではなく、版付き回帰シグナルです。

## 見直し条件

独立に収集した検索ログや、より大規模なレビュー済み関連性データが得られたときに見直します。現行版は過去比較用に保持します。
