# ADR-014: 期間の独立性チェックは厳密なまま保つ(近似化しない)

## Context

`packages/self-understanding/src/constructs.ts`の`tendencyScopeFor`は、過去の観測期間同士が互いに独立とみなせるかを判定し、それらを`totalSampleCount`に積み上げます。各期間について、`sourceEntryIds`の重なりをそれ以前に採用した全期間と比較しており(n期間・1期間あたりk件のsourceEntryIdsに対してO(n²·k))、この合計値は`relatively_stable_candidate`スコープの判定、さらに広くは`docs/evidence-thresholds.md`にあるすべてのサンプル数フロアに直結しています。

この点は、進行中のPCS/MeTheory閾値レビューの一環としてではなく、計算量分析の学習の一環として読み・検証したものです。同じ形の総当たり比較(O(n²)的なペア比較)はmy-searchの重複排除やPCSの適用条件重複チェックにも現れており、リポジトリごとに再発見するよりここで一度名前を付けておく価値があります。現在のデータ量ではこの関数は十分速く、nは1つの構成概念・条件・結果の組み合わせについて存在する過去期間の数に限られるため、個人の日記データでは小さい値(数千ではなく数十程度)にとどまります。

懸念は速度ではありません。もしこのチェックを、より大きいnに対応するために近似的な類似度手法(my-searchの重複排除で検討したLSHバンディングのような)に置き換えた場合、失敗の方向は非対称です。真の重なりを見逃すと、相関のある2つの期間が黙って独立とみなされ、重複した証拠で`totalSampleCount`が水増しされます。これは見逃し(洞察を逃す方向)ではなく、誤った確信を生む方向の失敗です。またこれはADR-005(決定論的な評価)およびADR-013(評価器を保存し、結果の再現性を保つ)とも衝突します。近似的でパラメータ調整を伴う重なりチェックは評価器の変更の一種であり、性能のために黙って差し替えてよいものではなく、ADR-013が要求するのと同じバージョン管理と独立期間での検証が必要になります。

## Decision

`tendencyScopeFor`の重なり/独立性チェックは厳密なまま保ちます。パイプライン全体で将来どのような性能改善が行われるとしても、速度を得るために近似的・サンプリングベースの類似度手法に置き換えることはしません。もし将来、nが実際に問題になるほど大きくなった場合は、近似に頼るのではなく比較範囲を制限・再構成すること(例: 考慮する過去期間数に上限を設ける)を優先し、そのような変更はADR-013のもとで評価器に影響する変更として扱います。

このADRは`docs/evidence-thresholds.md`の特定の閾値の変更を提案するものでも、それを評価するものでもありません。それは別途進行中の閾値レビューの範囲です。

## Consequences

- `totalSampleCount`は推定値ではなく、厳密な独立サンプル数を反映し続けます
- ここでは性能改善は許可されておらず、現在の観測データ量では必要もありません
- 将来の実装担当者(委任先を含む)が、このADRを読み返さずにこの関数を「最適化」しない理由を文書として持てます

## Reversal

実際の利用状況のプロファイリングでこの関数が測定上のボトルネックだと分かった場合のみ、かつADR-013が他の評価器変更に要求するのと同じバージョン管理・独立期間での検証と合わせて見直します。
