# ADR-008: ユーザー観測とシステム観測を両方保持する

## 背景
同じフィールドとエピソードに、ユーザー確認値、決定論的なシステム値、AI推論値が届くことがある。元ソースを見えるまま保持しつつ、評価には決定論的な値選択ルールが必要である。

## 決定
複数の観測がある場合、評価器は`user_confirmed`、`system`、`ai_inferred`の順で使用する。同じソース内で競合した場合は最新の観測を使う。元Provenanceは追記専用で保持し、システム値をユーザー値で削除せず、ユーザー値をAI推論で暗黙に置き換えない。

## 代替案

- A: 現行どおり、主観的な概念ではユーザー確認値を優先する。
- B: 自己申告より決定論的なシステム計測を優先する。
- C: どちらのソースも隠さず、乖離を別のレビュー可能な観測として保持する。

現行評価器はAを採用する。PCSが機械計測値を提供できるようになったため、Cは将来の乖離分析機能の方向性とする。実装には別のデータモデルとレビュー手順が必要である。

## 影響

- 優先順位と同率時のルールを文書化するため、評価結果を再現できる。
- ソース間の不一致を元観測から確認できる。
- 過去の元記録を変更せずに、将来の乖離表示機能を追加できる。

## 撤回方法
新しいバージョン付きソース選択ポリシーと移行計画を採用する。過去のProvenanceや完了済み分析を暗黙に再解釈してはならない。
